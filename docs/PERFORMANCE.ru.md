# Скорость распознавания · 0.2.0

[English и технические источники](PERFORMANCE.md) · [Замеры](benchmark-emulator.json)

## Что изменено

Android обрабатывает до двух записей одновременно. Модель общая, распознаватели независимы. При нехватке памяти, энергосбережении и существенном нагреве новые задания запускаются по одному; уже начатые завершаются. Экономный режим всегда использует один обработчик.

Декодирование не ждёт свободного входного буфера на каждом пакете. Звук передаётся распознавателю порциями по четверти секунды с повторным использованием памяти. Частота звука, параметры распознавания и вся речь сохранены. Если текст уже готов, модель вообще не загружается. После каждого файла результат сохраняется отдельно; «Стоп» завершает только процесс распознавания. Время до завершения оценивается по размеру файлов и прогрессу текущих записей, поэтому при разных битрейтах оценка может меняться.

## Результаты проверки

Эмулятор Android API 35, x86_64, четыре виртуальных ядра; три повторения, в таблице медианы. Вымышленная речь синтезирована локально, повторена пять раз с паузами и сохранена в MP3 64 кбит/с. Сравнение с циклом обработки версии 0.1.0. Загрузка модели исключена: отдельно заняла 1,16 с для русского и 0,55 с для английского.

| Пример | Длина аудио | Раньше, один файл | Сейчас, один файл | Сейчас, два одновременно | Ускорение очереди |
|---|---:|---:|---:|---:|---:|
| Русский, моно 16 кГц | 67,94 с | 6,62 с | 7,06 с | 7,84 с | 1,69× |
| Английский, стерео 44,1 кГц | 56,24 с | 7,13 с | 7,66 с | 8,48 с | 1,68× |

Ускорение очереди — удвоенное старое время одного файла, делённое на новое время пары. **Один файл стал обрабатываться примерно на 7% медленнее; выигрыш дала параллельность.** Распознанные слова в контрольных примерах не изменились. Это небольшой синтетический тест, а не проверка 500 звонков. Он не доказывает точность на телефонной речи или длительную скорость на физическом телефоне. Физический телефон не использовался.

Прошли проверки поиска на двух языках, отсутствующих слов, повторного запроса без загрузки модели, совместных фильтров, массового выбора только видимых записей, защиты от устаревшего прогресса и сохранения готового текста при остановке. На эмуляторе остановка подтверждалась в пределах 0,1 с.

## Дальнейшие варианты

Изучены компактный русский Zipformer int8, T-one для телефонной речи, whisper.cpp с квантованием и определением участков речи, ONNX Runtime Mobile и ускорение Qualcomm QNN. Ссылки и критерии сравнения находятся в [техническом отчёте](PERFORMANCE.md#methods-reviewed-not-yet-shipped).

Эти модели пока не заменяют текущую Android-модель: в выпуске используется Vosk на процессоре. Ускорение GPU/NPU требует совместимой модели и замеров на конкретном устройстве. Ограничивать распознавание только искомыми словами рискованно: можно потерять контекст и получить ложные совпадения. Агрессивное удаление тишины также может отсечь тихую речь. Для следующего изменения важны прежде всего пропуски ключевых слов, адресов и чисел, а затем скорость.

## Как проверить самостоятельно

1. Выберите небольшую группу новых записей, где заранее известны совпадения и их отсутствие. Ничего никуда отправлять не нужно.
2. После проверки запишите время, скорость и количество пропущенных или лишних совпадений. Скорость `10×` означает десять минут аудио за минуту обработки. Для сравнения с экономным режимом нужна другая, ещё не обработанная группа сопоставимой длительности: повтор по кэшу не измеряет распознавание.
3. Измените запрос для тех же файлов: должен использоваться готовый текст. Прервите новую группу и продолжите — завершённые файлы должны пропускать повторное распознавание.

Чтобы уложиться в 30 минут, требуемая скорость равна общей длительности аудио в минутах, делённой на 30, с запасом на подготовку. Для десяти часов нужна скорость выше 20×, для одного часа — выше 2×. Количество файлов и мегабайты сами по себе этого не определяют.
